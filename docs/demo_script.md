# adviSU — Demo Script

Doubles as the shot list for the recorded demo video (CLAUDE.md Section 7.4).
Target length: **6–8 minutes**. Keep every claim checkable; never show a number the system did
not actually produce.

## 0. Before you hit record

```bash
# backend (must run from server/ — CHROMA_PERSIST_DIR is cwd-relative)
cd server && myenv/Scripts/python -m uvicorn main:app --reload

# frontend
cd frontend && npm run dev
```

Checklist:
- [ ] `.env` has `GROQ_API_KEY` and a reachable `MONGO_URI`
- [ ] Chroma has the corpus: `npm run validate:data` reports 0 errors
- [ ] The demo student's profile is set (CS, curriculum term 202401) and has a course history
- [ ] Browser zoom ~110%, window 1600×900, notifications off
- [ ] Have `outputs/tables/retrieval_metrics.csv` open in a second tab for the evaluation section

---

## 1. What this is (~40 s)

Open on the login screen — the adviSU lockup is the hero image.

> "adviSU is a retrieval-augmented academic advising assistant for Sabancı University. It answers
> questions about degree requirements from the official curriculum data, and — importantly — the
> numbers it reports are computed in code, not by the language model."

Sign in. Land on the chat page.

## 2. Grounded advising answer (~90 s)

Ask, in the chat:

> `What are the area elective requirements for my program?`

Point out on screen:
- The answer cites sources; the source cards name the actual requirement chunks.
- Retrieval was **scoped to this student's program and curriculum term** before ranking — a CS
  student never sees IE requirements.

Then a Turkish question, to show the assistant answers in the user's language:

> `Mezuniyetime kaç kredi kaldı?`

## 3. The deterministic degree audit (~90 s) — the strongest part

Go to **Profile** in the sidebar. Show the profile (major, curriculum term) and the audit table:
SU categories, engineering / basic-science ECTS, missing required courses.

> "This table is not generated by the LLM. `degree_audit.py` reads the official requirement file
> for exactly this program and curriculum term plus the student's course history, and computes the
> category allocation in code — including elective overflow and either/or course choices. The audit
> JSON is then handed to the model as authoritative context, and the prompt tells it to explain
> those numbers, not to recompute them."

Back in chat, ask a graduation question and show the answer agreeing with the table.

## 4. Safety: it refuses instead of guessing (~60 s)

Two deliberate misses:

> `What time does CS 455 meet on Mondays?`

> "Schedule data is not in the corpus. The honest answer is that it doesn't know — and that is what
> a system students would actually rely on has to do."

Then the missing-data gate: switch the profile to a curriculum with no official file (e.g. IE
202101) and ask a graduation question.

> "It does not fall back to another program's or another year's requirements. It says the exact
> curriculum is unavailable. A wrong-but-confident audit is worse than no audit."

## 5. Retrieval modes — the evaluation angle (~90 s)

Use the **Retrieval mode** selector in the header. Ask the *same* question three times:

1. `Hybrid + CrossEncoder Reranking` (default) — grounded, with sources
2. `BM25 RAG` — lexical only
3. `LLM-only baseline` — note the amber warning bar, and that **no source cards appear**

> "LLM-only is the control condition. It has no access to the curriculum data, so whatever it says
> about Sabancı requirements is unverifiable — which is exactly what we set out to measure."

## 6. Measured results (~90 s)

Switch to the terminal / the CSV tables.

```bash
npm run benchmark:build   # regenerate the benchmark from the corpus
npm run eval              # all five modes over the benchmark
npm run eval:tables       # report-ready CSVs
```

Show `outputs/tables/retrieval_metrics.csv` and `failure_summary.csv`. Talk through:
- ground truth is **read out of the corpus**, so the benchmark cannot drift from the data
- the per-mode Recall@k / MRR / nDCG comparison
- the failure breakdown, including the finding that reranking currently *hurts* recall on this
  corpus (see `docs/experiment_log.md` for the measured numbers and the explanation)

> "We are reporting what we measured, including the result that went against our expectations."

## 7. Close (~30 s)

> "Built for CS 455; we've kept developing it since the course ended. Next steps are course
> schedules, so recommendations are backed by real offerings, real authentication, and a wider set
> of programs."

## Questions to avoid on camera

These have known weak spots (CLAUDE.md §H). Don't demo them without narrating the limitation:
- Course **recommendations** — schedule and offering data are not ingested, so recommendations
  lean on the requirement corpus only.
- Anything needing an **instructor name or meeting time** — not in the corpus (unless you are
  deliberately demoing the refusal, as in §4).
- **GPA** requirements — no GPA data is collected.
- Turkish curriculum lookups phrased very differently from the corpus wording — cross-lingual
  retrieval is a measured weak point.
